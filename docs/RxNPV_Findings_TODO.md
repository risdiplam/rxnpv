# RxNPV — Running findings / to-do list

Not a build log (that's `RxNPV_External_Suggestions_Tracker.md`). This is a living list of things identified as worth fixing or investigating further, added as found, checked off (with a one-line resolution note, not deleted) once actually resolved. Ordered roughly by how much it matters, not when it was found.

Severity key: 🔴 real risk/bug · 🟡 worth doing, not urgent · 🔵 investigate further, not yet confirmed as an issue · 🟢 fixed

The bulk of this list came out of an exhaustive audit pass (September 2026) covering the backbone, engine math, external integrations, charts, accessibility, security and documentation. Nearly all of it has since been fixed — the fix work is in the git history between `8f9d350` and `63969cc`, each commit explaining what was wrong and why the fix is shaped the way it is. What remains open is listed first.

## Fixed

### 🟢 Electron upgraded 33.4.11 → 44.4.4 (eleven majors), and what it actually changed
Deferred by the user on 2026-09-21 because it needed their time; done 2026-09-22 with almost all of the verification automated after all.

**What moved:** Electron 33.4.11 → 44.4.4 (Chromium 130 → **152**, Node 20 → 22), electron-builder 25.1.8 → 26.15.3 (25 predates Electron 44 and would not have packaged it). `npm audit` went from **14 findings to 0** — all fourteen were in packaging-time tooling, exactly as the original assessment said, and they are simply gone now.

**The one user-visible consequence:** the bundle's `LSMinimumSystemVersion` rose from **11.0 to 13.0**. This machine runs macOS 26.6.2 so it does not matter here, but the app will no longer launch for anyone on macOS 12 or earlier — worth knowing before sharing it.

**Most of the "only a human can check this" list turned out to be automatable**, which is the useful finding. A throwaway Electron script driving the real main-process APIs with no save dialogs verified, under 44: `loadFile` ok · `printToPDF` producing a 27,577-byte file with a valid `%PDF-` header · `capturePage` non-empty and returning the requested rect at the display's real 2× device pixel ratio · `nativeImage.resize` and `toDataURL` ok · **`minWidth` still clamping** (a request for 500×400 came back as 900×600). Separately, through the running app itself: the CSP hash still validates under Chromium 152 (the app renders, which it would not if the hash had broken), all seven `contextBridge` methods are exposed, and all four network paths work — the EDGAR main-process bridge returned HTTP 200, and CT.gov, CMS and Europe PMC all fetched through the CSP.

*One false alarm worth recording so it isn't re-investigated:* the probe's own direct `fetch` to SEC returned **403**. That was the probe sending its own User-Agent rather than the app's `EDGAR_USER_AGENT` — through the app's real bridge the same URL returns 200 and parses. SEC rejects unidentified clients; it was not an Electron regression.

**Verified on the installed app**, launched from `/Applications` on the new runtime: reports Electron 44.4.4 / Chromium 152, renders, and the real saved data is intact — the Stok Therapeutics case with its Elsunersen phase-3 program, one watched trial, one custom comp, zero leftover `pdcf_` keys, zero console errors. Local Storage was backed up to `~/Documents/rxnpv-backups/localstorage-pre-electron-upgrade-*` first and the backup confirmed to contain the case data before anything was touched.

**What still genuinely needs a human** is now only the two native *save dialogs* (a panel has to appear and write a file — `printToPDF` and `capturePage` themselves are proven) and a subjective look at window resize/reopen. Roughly three minutes, not ten.

### 🟢 Two CT.gov engines both declared `ctgovFetch`, and the Tools-side timeout was being silently discarded
Found while building the trial decoder. `ctgovEngine.js` and `ts_ctgovEngine.js` each declared a top-level `async function ctgovFetch`; because the latter is concatenated second, its definition replaced the former for the entire bundle. Every Tools-side CT.gov call — Trial Explorer, competitor landscape, Catalyst Calendar — was therefore running through an implementation with **no timeout at all**, while its own source clearly specified a 15-second abort. A hung request hung forever. Renamed to `tsCtgovFetch` and given its own timeout.

**This also corrects an earlier conclusion in this document.** The "two engine families" item was previously closed as "completely disjoint function surfaces" — that was wrong, and wrong for an instructive reason: the check used a grep matching `function` at line start, which silently skipped every `async function` in both files. An async-aware sweep across all 33 modules now confirms this was the only collision, and that sweep is the one to repeat, not the original.


### 🟢 Persisted storage keys renamed off the old project prefix
Every localStorage key was prefixed `pdcf_`, after this project's earlier name — invisible to users, but present in the public repo and a guessable contraction of that name. The last identity breadcrumb. Renaming alone would have orphaned every saved case behind a key nothing reads any more, so `migrateLegacyStorageKeys()` (`app.js`) copies each key forward and removes the original **only** after reading the copy back byte-identical; a failure leaves the original untouched and retries next launch. Caches are discarded rather than migrated (they re-fetch in seconds and would waste quota the cases need). `window.pdcfSimBridge` is runtime-only and was renamed outright. **Verified against real data**, not just a simulation: storage backed up to `~/Documents/rxnpv-backups/` first, then confirmed via CDP on the installed app that the saved case survived with its program intact, the theme carried, and no `pdcf_` keys remained. It also carried forward a watched-trial snapshot and a custom peak-sales comp that a raw scan of the leveldb files had **not** revealed — which is precisely why the migration iterates live `localStorage` keys rather than a hand-built list. One stray `pdcf_cb` string appears in the leveldb files but matches no source reference in any commit and no live key; it is a remnant of a deleted record and is correctly ignored.

### 🟢 Code signing / notarization — decided against, not deferred
Moved to CLAUDE.md's "Deliberately not built". $99/yr for an Apple Developer account buys exactly one thing: removing the Gatekeeper prompt for someone who *downloads* the app. It does nothing for the user's own use, because a locally built app never gets a `com.apple.quarantine` flag — confirmed, the installed copy has none, which is why it opens with no warning. For a personal tool that is not worth an annual fee, and anyone it is shared with can still run it via the manual override in System Settings → Privacy & Security. **Should not be re-raised as a gap.** Revisit only if Apple removes the manual override, or if the app is ever distributed at scale. Separately, README's Gatekeeper instructions were stale (they described the Control-click → Open shortcut, which current macOS no longer honours) and were rewritten to point at the Privacy & Security override without over-specifying a click path that keeps changing between releases.


### 🟢 The company's own COGS and marketing were charged against royalty income
The last open modelling question from the audit, now resolved with a worked example rather than left as a suspicion. In a licensed-out territory the *partner* manufactures and sells — that is the whole economic trade of the deal: less revenue, but close to pure margin and no commercial infrastructure to fund. `computeProgramPnL` was applying the licensor's own COGS% and marketing% to revenue that had already been royalty-substituted. Hand-checked on a $500M-peak programme with a 15% global royalty, 15% COGS and marketing at 20% of peak: **$48.8M reported against a correct $75.0M — a 35% understatement** of the partnered asset. `applyPartnershipToRevenue` now tags each year's royalty portion and reports peak commercial revenue separately; COGS and marketing apply only to the commercial side. A territory-limited deal still pays full freight on the business the company actually sells itself, and a test asserts exactly that. Sales force is deliberately left alone — it is an explicit headcount the user types rather than a revenue-derived figure, so zeroing it would silently override a deliberate input; the partnership panel now says to set reps to zero for a fully licensed-out programme. Note this **changes existing valuations**: a saved case with a royalty deal will now show higher partnered profitability, which is the correct number, and the DCF moves with it since `computeProgramValuation` shares this function.

### 🟢 Scientific notation was rendered flat
`Cmax`, `Ka` and `K_D` (with a literal underscore) were written without their subscripts, which reads as sloppy to anyone who works with them daily. `sci()` now renders known tokens with real `<sub>` elements for the DOM, and `sciText()` uses Unicode subscripts for SVG chart labels where `<sub>` is not valid markup. Case is corrected alongside position, because that part carries meaning: a rate constant is lower-case k (k<sub>a</sub>, k<sub>e</sub>) while an equilibrium constant is upper-case K (K<sub>D</sub>) — writing both as "K" loses a real distinction. Routing `field()` and `note()` through the helper covers every labelled field and collapsed note in Simulation, not just the ones spotted by hand. **Two things only the visual check caught**: wrapping each token in its own `<span>` inherited `.field span { display: block }` and broke every label onto two lines, so tokens are emitted as flat siblings instead; and default `<sub>` styling disturbs line-height, which is obvious in a dense form, so it is pinned explicitly. Left alone deliberately: "Alpha" is a spelled-out word with a plain gloss rather than a mangled symbol and is clearer that way for this audience, percentiles (P10/P90) are conventionally flat, and the meta-analysis output already used a proper superscript I².

### 🟢 The two overlapping engine families are not a divergence risk — checked
`ctgovEngine.js`/`fdaEngine.js` (Tools) vs `ts_ctgovEngine.js`/`ts_fdaEngine.js` (Simulation). Their function surfaces are **completely disjoint** — not one shared name — and the only genuine overlap, two CT.gov study parsers, reads *identical source paths* for every field they share (`status.overallStatus`, `design.phases`, `design.enrollmentInfo.count`, `status.startDateStruct.date`). They differ only in how each presents a missing value: Tools shows `"N/A"` for an absent phase and `""` for an absent status, Simulation leaves both empty. That is a display choice appropriate to each context, not divergent logic, and nothing compares the two. The field sets differ because the purposes do — Trial Watch needs outcomes/conditions/interventions for diffing, historical comps needs completion dates for duration maths. Confirmed intentional; no action needed.


### 🟢 Old-name files existed outside the git repo, including in iCloud
The rename/scrub earlier in the project was scoped to the git repository and succeeded completely *within that scope* — but a filesystem-wide check found substantial leftovers outside it: two 698MB `PharmaDCF 11.app` bundles (one in `Documents/Projects` as a direct sibling of the live project, one in `Downloads`), a stray unwrapped app bundle sitting loose in `Documents/Projects/Contents/`, `pharmadcf-handoff.zip`, eight `BioLens_*.html` prototypes in `Downloads`, a BioLens crash-report stub in `~/Library`, a stale BioLens build artifact inside the project's own `electron/dist/`, and — most importantly — four `PharmaDCF*` documents in **iCloud Drive**, actively syncing to Apple's servers and any other device on the same Apple ID.

**Resolved**: all of it moved (not deleted, at the user's direction) to `~/Documents/rxnpv-oldname-quarantine-20260921/` — 2.1GB, fully reversible, and out of iCloud and Downloads. A filesystem-wide `mdfind` re-scan afterwards confirms zero old-name residue anywhere outside that quarantine folder. The folder is the user's to empty whenever they want. One item needed no action: an entry for `BioLens.app.backup-20260823-012109` traced to a stale Launch Services database record for an app that no longer exists on disk.

### 🟢 The packaged app could not launch without an internet connection
React was loaded from unpkg at runtime, so with no network the scripts failed, `React`/`ReactDOM` were undefined, and the entire inline bundle — including `ErrorBoundary`, itself a React component — never ran, leaving a blank window with nothing on screen to explain it. Directly contradicted the app's whole premise as a local, personal tool: a user with no connectivity couldn't open even their own saved cases. **Fixed** by vendoring React 18.3.1's UMD builds into `electron/vendor/`, committed and packaged, pinned to an exact build rather than a floating `@18` range. Confirmed present inside the packaged `app.asar`.

### 🟢 EDGAR extraction silently misstated real company financials
Four confirmed bugs, each with a hand-built fixture, in code that feeds SEC filing data straight into capital-structure, dilution and runway maths — and which the test harness never even loaded.
- **Cash runway off by 2x in Q2 and 3x in Q3 for most filers.** A single 10-Q reports the same income-statement tag for both the standalone quarter and the year-to-date span, both ending on the same date; sorting only by end date left the choice to array order, and treating a six-month loss as one quarter's burn halved the runway. Now classified by the span actually covered (`periodMonths`), shortest span winning a tie. A 10-K filer reporting only a full year is now usable too, instead of skipped.
- **Convertible notes undercounted.** Stopped at the first matching tag, so a note split across current and noncurrent lines reported only one side ($15M of a $20M balance). Now summed, with the tag families made symmetric and a guard against double-counting a filer that reports the combined total alongside its parts.
- **Warrants, options and debt undercounted for multi-tranche issuers.** Same-date rows are now summed — but identical values are collapsed first, so an amended filing restating the same fact isn't double-counted. Per-share exercise prices are deliberately excluded: two $25 strikes are not a $50 strike.
- **Shares outstanding understated by ~34% right after a capital raise.** The fallback chain ranked the EPS weighted-average (a period *average*) above `CommonStockSharesIssued` (a real point-in-time balance). Point-in-time tags now come first, a period average is a flagged last resort, the form filter its siblings use was added, and a USD fact can no longer be returned as a share count.

### 🟢 A royalty deal had zero effect in the app's own default mode
Quick revenue mode puts all revenue in `usRevenue` and never renders the territory selector, so the default `"exUS"` applied the royalty to a base of zero while full commercial revenue passed through untouched — a user who typed 15% saw exactly the number they'd see with no deal at all, and Quick mode is the default for every new program. **Fixed**: Quick mode has a single revenue figure, so a deal on it is a deal on all of it, and it now resolves to global rather than honouring a territory the UI never let the user set. Full mode is unchanged.

### 🟢 Simple Multiple valuation silently dropped all upfront and milestone value
The logic was inline in `computeCaseValuation`, and both consumers read the result defensively as `partnershipValueAdded || 0`, so a case with a $100M upfront quietly showed that much less under Simple Multiple than the identical deal under DCF — while a comment claimed the bridge worked under either method. **Fixed** by extracting `computePartnershipContribution` and calling it from both paths; a regression test now asserts the two methods credit the same deal equally.

### 🟢 R&D cost could vanish entirely or land in the wrong year
`launchYearOffset` and the R&D item timeline are set independently and nothing kept them in sync. A launch year of 0 — the value the field's own placeholder suggests for "launches immediately" — hit an early return that dropped the entire remaining R&D spend out of the cash-flow calendar, overstating NPV by its full value. A launch year merely *shorter* than the timeline dumped every later stage's cost into a single year, which conserved total dollars but mispriced them badly since a DCF discounts each year separately. **Fixed**: the window is never zero when real cost exists, and a timeline longer than the window is compressed proportionally, preserving each stage's relative share and ordering.

### 🟢 A live-API outage looked identical to "no data found"
For a tool used to check whether insiders are selling or whether a drug is approved, "we couldn't reach the server" and "there is nothing there" are completely different answers — and all three integrations rendered them the same way. **Fixed across the board**: FDA Lookup, which had no error state at all and read only the fulfilled branch of `Promise.allSettled`, now distinguishes total failure, partial failure and a genuine zero-result response, and its fetcher aborts at 15s instead of hanging on "Searching…" forever; `findCIK` no longer collapses "no such company" and "SEC unreachable" into one null; Catalyst Calendar counts and reports per-source failures instead of dropping them on the floor.

### 🟢 Four live searches had no protection against out-of-order responses
Company Lookup, competitor search, Trial Explorer's comp search and its trial check all fired fetches with no generation guard, so correcting a search mid-flight could leave one company's data on screen under another company's name with nothing indicating it. All four now ignore superseded responses.

### 🟢 Chart rendering broke at data extremes
An invalid SVG attribute is silently dropped by the browser rather than raising anything, which is why these went unnoticed — they render as quietly missing elements, not errors. Fixed: `ScatterChart` inverted its axis on all-negative data (headroom was multiplied into a negative max instead of added above it); `renderLineChart` hard-coded `yMin` to 0 so negatives were clipped out of sight; a single-point line series drew literally nothing; an all-identical histogram labelled its axis "100, 100.5, 100"; `renderForestPlot` emitted `x="NaN"` ticks with nothing to anchor a domain, and drew a self-intersecting bowtie instead of a diamond for a reversed pooled interval.

### 🟢 Custom comp entry silently saved blank numeric fields as real zeros
Only the first field was ever required, so `parseFloat("") || 0` turned a blank deal value into a genuine $0 entry, merged into the same array as the built-in source-verified comps and quietly dragging down any average or multiple derived from that table. Numeric fields must now parse, and the specific offending field is named rather than just disabling the button.

### 🟢 The Therapeutic Area dropdown steered users to generic benchmarks
The three benchmark tables come from different papers and don't share a taxonomy — PoS data is filed under Neurology/Autoimmune/Infectious disease/Urology while cost and duration use CNS/Immunomodulation/Anti-infective/Genitourinary for the same diseases. `THERAPEUTIC_AREAS` is the union, so the dropdown offered both halves of each pair and picking the "wrong" one silently fell back to a generic weighted average despite a perfectly good area-specific number existing under the other name. **Fixed** with an `AREA_ALIASES` map that resolves the synonym and reports which name the data was actually found under. No benchmark value was restated.

### 🟢 PK/PD printed "half-life Infinityhr", and validated nothing
Ke = 0 is a legitimate input and `ln(2)/0 = Infinity` is correct maths, but the raw value was string-concatenated into the headline. Formatting now lives next to `halfLife()` in the engine so a caller can't reintroduce a raw `.toFixed()` on an infinite value. Separately, PK/PD was the one Simulation tool that validated nothing — a blank or zero dose/Vd/window produced a confidently-rendered garbage profile. It now refuses bad input like its siblings, while keeping Ke = 0 legal.

### 🟢 A program that failed to compute vanished from the company rollup
Excluding it is correct — one half-filled program shouldn't take the whole case down — but doing it silently was not: the headline valuation simply came out lower with nothing saying so. The rollup now names what was left out and states that every total on the page excludes it.

### 🟢 Peak Sales Monte Carlo broke on a blank Iterations field
`Math.max(1000, NaN)` is `NaN`, not 1000, so the trial loop never ran and the headline rendered "$NaN". Confirmed live on the packaged app before and after. Two engine files also had a dormant `require('./statsEngine.js')` pointing at a file that doesn't exist (it's `ts_statsEngine.js`) — harmless under both real load paths, but a landmine for whoever next touches the build.

### 🟢 A negative option/warrant strike manufactured impossible dilution
`treasuryMethodShares` guarded count, price and out-of-the-money but not a negative strike, which inverted the arithmetic and returned more net new shares than the option pool contains. Now matches the guard `ifConvertedShares` already had.

### 🟢 Insider Transactions read as "no insider activity" when it wasn't
The tool only ever parses non-derivative Form 4 activity — direct buys and sells — so a CEO's large option grant is invisible to it, while the empty state said simply "No transactions found". Reworded to state what it actually covers, and the limitation is now recorded in CLAUDE.md's feature list too.

### 🟢 No Content-Security-Policy anywhere
Now runs under a restrictive one: `default-src 'none'`, no remote script, and `connect-src` locked to exactly the three hosts the research tools query. The app is a single inline `<script>`, which a CSP blocks by default, so `build.js` computes the sha256 of that exact bundle and injects it — nothing but this build's own script can execute. **Worth knowing for anyone touching this**: jsdom does not enforce CSP, so the whole test suite stays green against a policy that blanks the real app. The first attempt did exactly that (it hashed `combined` directly, missing the newline after `<script>`), and a hand-written verification reproduced the same off-by-one and also reported success. Verified via CDP against the installed app: React loads, `#root` mounts, zero violations, zero console errors.

### 🟢 Accessibility: focus trap, select labels, keyboard-unreachable links
First accessibility work on the project — contrast had been checked rigorously, keyboard and screen-reader behaviour never had. The delete dialog now traps Tab (it previously let a keyboard user tab into the editor behind the dimmed overlay and start editing fields they couldn't see), carries `role="dialog"`/`aria-modal`, and returns focus to whatever opened it. All 15 hand-built `<select>` elements now have an `aria-label` — several previously announced as anonymous combo boxes. Three `<span onClick>` actions that Tab skipped entirely ("Tools → Licensing Comps" and both "Watch this trial" links) are now keyboard-reachable. The two-step delete button's armed state got an `aria-live` announcement.

### 🟢 Sum-of-the-Parts didn't tax-shield G&A like the combined valuation
It subtracted raw pre-tax G&A while valuing every program after tax, so with tax modelling on the parts stopped reconciling with the combined number by roughly `taxRate × G&A` per year — contradicting a comment claiming they were guaranteed consistent. G&A's drag is now the difference between the taxed calendar with and without it, which gets NOLs and zero-tax years right by reusing `applyTaxToCalendar` rather than re-deriving a rate. No behaviour change when tax is off.

### 🟢 Test coverage gap on the functions that touch real money
`edgarEngine.js` was never loaded by the test harness at all. The suite went from 568 to 650 checks, with new regression tests covering every fix above — each built from the exact fixture that reproduced its bug, so they fail against the old code. Two of those new tests initially failed and turned out to be bad fixtures of mine rather than code bugs, which is the discipline `test/README.md` warns about: a verification suite's failures are as likely to be wrong as the code.

### 🟢 Documentation accuracy
Both CLAUDE.md and README.md said "32 plain JavaScript files" (it's 31). README claimed `electron/dist/` "gets wiped on a clean rebuild" — it isn't, which is how a stale artifact under the old product name survived every rebuild for a month. `test/README.md` advertised 130 math checks (it's 650) and stated flatly that no real network calls happen, which read as contradicting CLAUDE.md's live-API claim — both are true and describe different things, and now say so. CLAUDE.md gained notes on the vendored React, the CSP hash and its two failure modes, the Form 4 scope limit, and the benchmark-table taxonomy split.

### 🟢 `wideField` dead code
Confirmed unreferenced via word-boundary search and deleted. The `.field-wide` CSS class it shares a name with is still used elsewhere and was left alone.

## Verified clean — checked, not assumed

- **Catastrophe recovery is real**: a fresh `git clone` of the public repo, with no connection to the working folder, builds, packages and launches a working app. Confirmed by doing it.
- **IPC boundary is correctly scoped**: `edgar:fetch` hostname-locked to `sec.gov`, `open-external` scheme-locked to `http(s)`, and `main.js` ↔ `preload.js` have perfect 1:1 parity across all six channels with no orphans either side. `BrowserWindow` runs with `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, no `webSecurity: false`, and no dev-tools auto-open.
- **No injection risk**: every chart-render path runs text through `escapeXml`; no `dangerouslySetInnerHTML`, `eval` or `new Function` anywhere in the shipped app.
- **Zero memory/listener leaks**: every subscription set up in a `useEffect` has a correctly-scoped cleanup; the one vanilla-DOM renderer rebuilds its subtree wholesale so its listeners can't accumulate.
- **13 of 14 empty `catch (e) {}` blocks are legitimate** degrade-gracefully patterns; the one real exception was the company-rollup drop-out, now fixed.
- **Hand-verified against worked numbers**: the whole of `capitalEngine.js` (treasury method, if-converted notes, the full capital-structure bridge, `applyFutureRaise` and its composition with the dilution path); the Peak Sales Monte Carlo triangular sampler including all three degenerate cases, and its percentile interpolation; `computeRnDToLaunch`; `computePrelaunchSalesForceCost`; all six `computeRedFlags` checks, each with a trigger *and* a near-miss non-trigger case; `aggregateCompanyRevenue`'s calendar alignment for a later-launching program; the milestone and cost-sharing formulas; `brierScore`; `computeForwardRunway`'s crossing interpolation; PRV valuation; `computeBinaryEventImpliedPoS`; the Non-Inferiority decision rule; the survival-curve derivation from the hazard ratio; `diffTrialSnapshots`; FDA Orange Book patent parsing; Historical Comps' median/status rollup; case duplication (a real deep clone with fresh IDs).
- **No secrets, no hardcoded local paths, no identity metadata** in tracked source or in the icon files; all commit authorship is the intended pseudonymous identity.
- **`electron/package.json` is clean** — minimal `files` allowlist, no postinstall hooks, no risky builder config.
- **`test/`'s own npm dependencies**: 0 vulnerabilities of any severity.
- **`MODULE_ORDER` is exactly correct**: 31 files, 31 entries, zero missing, duplicate or orphaned.
- **A real visual pass on the packaged app**: no layout overlap or broken reflow at a substantially narrowed window. (One apparent finding was a false alarm worth recording so it isn't re-investigated: a screenshot of the window while it wasn't frontmost rendered with a 3D perspective skew — an artifact of the capture tool, not the app. Bringing it to focus showed normal rendering.)
